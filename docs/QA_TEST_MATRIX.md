## บั๊กที่เจอและแก้ (ทั้งหมดมี regression test)
1. **สกัดข้อมูลเอกสารได้ว่าง** — เพดาน output ของแชต (600 โทเคน) ตัด JSON ของโปรไฟล์ → สถานะ "done" แต่ข้อมูลว่าง และเผาโควตา AI. แก้: เพดานแยก 8,000, JSON mode, timeout 120s, ผลว่างขึ้น error (`eca312c`)
2. **จองซ้อนเวลาเดียวกันได้** — AI ส่งชื่อหมอ "หมอสมชาย" แต่โปรไฟล์ "ทพ.สมชาย" ระบบมองเป็นคนละคน. แก้: เทียบชื่อโดยตัดคำนำหน้า (`_same_staff`), ใช้ชื่อ canonical, ตรวจตารางเวรได้ถูกต้องด้วย
3. **โควตา AI หมดระหว่าง RAG → ลูกค้า LINE ไม่ได้รับคำตอบเลย** — แก้: RAG degrade เป็นโปรไฟล์อย่างเดียว แล้วบอทส่งข้อความโควตา/ส่งต่อเจ้าหน้าที่
4. **สมัครด้วยรหัสผ่านสั้นได้** — บังคับ ≥ 8 ตัวอักษร
5. **อัปโหลดทั้งโฟลเดอร์ไม่ได้** — เพิ่มปุ่มเลือกโฟลเดอร์ + ลากโฟลเดอร์, ข้ามไฟล์ไม่รองรับ, อัปโหลดทีละ 3, แจ้งจำนวนที่ข้าม/ล้มเหลว
6. lint error (`reconcileTenant`), pymongo 4.7.3 ช่องโหว่ → 4.19.0

## ที่ยังต้องให้คนทดสอบ / ข้อจำกัด
- LINE จริงจากมือถือ (ที่ทดสอบจำลอง webhook ที่เซ็นลายเซ็นจริง ข้อความขาออกถูกจับไว้ ไม่ได้ยิง LINE API)
- Facebook Messenger (ยังไม่ได้ตั้ง `FB_*`), Google login กับบัญชีจริงหลัง deploy ล่าสุด
- เอกสาร "ทีมแพทย์" ใช้เวลาสกัด ~1.5–2 นาที/ไฟล์ (45 คน) — ปกติแต่ควรบอกลูกค้า
- ค่าเริ่มต้น `AI_TENANT_DAILY_TOKEN_CAP=100000` ต่ำสำหรับ onboarding + แชตวันแรก — ปรับบน Render ตามต้นทุนที่รับได้
- ทดสอบ Redis เป็นรุ่น 3.0 (GETDEL ไม่มี — harness ใส่ shim); production (Upstash) รองรับ
